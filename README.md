# FOCES Technical Events Listing Hub

A fast, highly intuitive, and fully responsive events aggregator platform created for the **Forum of Computer Engineering Students (FOCES)**. This web application serves as a unified digital ecosystem where students can seamlessly discover, search, and initiate registration for upcoming technical workshops, bootcamps, and hackathons.

## 🛠️ Technology Stack & Architecture Choices

### 1. Structure & Interface (`HTML5`)
* **Semantic Architecture:** Designed utilizing clean HTML5 semantic structural landmarks (`<header>`, `<nav>`, `<main>`, and `<footer>`) instead of generic divider nests. This guarantees highly structured, readable source code and ensures standard compatibility with native browser accessibility frameworks.

### 2. Styling & Layout Engine (`Tailwind CSS v4`)
* **Dynamic Grid Layout:** Implemented an optimized grid interface that automatically transitions from single-column vertical stacks on mobile platforms (`grid-cols-1`) to multi-column matrices (`md:grid-cols-2` and `lg:grid-cols-3`) on widescreen displays.
* **Persistent Elements:** Applied sticky layout parameters (`sticky top-0`) to the navigation matrix to keep core user interaction vectors constantly accessible during heavy scrolling.

### 3. Application Logic (`Vanilla JavaScript ES6+`)
* **Dynamic DOM Mutations:** Avoided the overhead of complex, heavy modern frameworks. The application uses clean JavaScript template strings to dynamically mount structural objects inside the Document Object Model.
* **Compound Search Filters:** Uses high-performance linear array operations (`Array.prototype.filter()`) mapping both input events (`input`) and selection dropdown mutations (`change`) simultaneously in real time.

## ⚙️ Development Setup & AI Use Disclosure

* **IDE Environment:** Developed locally utilizing Visual Studio Code.
* **AI Tools Utilization:** An AI companion was leveraged during the initial conceptual phase to generate structural HTML wireframe mockups and standard Tailwind utility layouts. These blocks were subsequently refactored manually, structured around correct semantic markers, and linked directly to the application state engine arrays.
* **Version Control Management:** Maintained a clean, logical step-by-step Git architecture separating structural implementations, presentation layouts, filtering engines, and system documentation.
